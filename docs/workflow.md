# วิธีทำงานร่วมกัน 7 คน

## หลักการเดียวที่ต้องจำ: หนึ่งคน = หนึ่งไฟล์

ไฟล์ของกฎแยกกันคนละไฟล์ใน `masking/engine/rules/` และเทสต์แยกกันคนละไฟล์ใน `tests/`
ถ้าทุกคนแตะเฉพาะไฟล์ของตัวเอง **จะไม่มี merge conflict เลย**

ไฟล์ที่ห้ามแก้เองโดยไม่บอก Lead (เพราะทุกคนใช้ร่วมกัน):

- `masking/engine/types.py` — สัญญากลาง
- `masking/engine/base.py` — คลาสฐาน
- `masking/engine/masker.py` — orchestrator
- `masking/engine/registry.py` — ทะเบียนกฎ

## ขั้นตอนทำงาน

```bash
git checkout main && git pull
git checkout -b feat/rule-email          # ใช้ชื่อ branch ตามตารางใน README
# ... เขียนโค้ด + เทสต์ ...
pytest tests/test_email.py -v            # เทสต์ของตัวเองผ่านก่อน
pytest                                   # แล้วเทสต์ทั้งชุดต้องไม่พัง
git commit -m "feat(email): mask username เหลือตัวแรก"
git push -u origin feat/rule-email
```

แล้วเปิด PR ให้ Lead review

## Checklist ก่อนเปิด PR

- [ ] `pytest` ผ่านทั้งชุด (ไม่ใช่แค่ไฟล์ตัวเอง)
- [ ] ลบ `pytestmark = pytest.mark.xfail(...)` ออกจากไฟล์เทสต์ของตัวเองแล้ว
- [ ] ลบ `NEVER_MATCH` ออกจาก pattern แล้ว
- [ ] มีเทสต์ทั้งเคส "ต้องจับ" และเคส "ต้องไม่จับ"
- [ ] เติมคำอธิบาย regex ของตัวเองใน `docs/regex.md`
- [ ] `ruff check .` ไม่มี error

## ทำไมกฎถึงเป็น stub ตั้งแต่วันแรก

เพื่อไม่ให้ใครต้องรอใคร — stub คืนข้อความเดิม แปลว่าเว็บและ API รันได้ตั้งแต่วันแรก
คนที่ 6 (frontend) และคนที่ 7 (deploy) จึงเริ่มงานได้ทันทีโดยไม่ต้องรอ regex เสร็จ
